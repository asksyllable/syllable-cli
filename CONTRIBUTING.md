# Contributing

## Repo layout

- Go code: `scripts/syllable-cli/` — `go build` and `go test` run from here.
- `Casks/syllable.rb` — auto-generated by GoReleaser, do not hand-edit.
- `.goreleaser.yaml` and `.github/workflows/` — release pipeline config.
- `scripts/syllable-cli/internal/spec/openapi.json` — embedded OpenAPI spec; the CLI's source of truth for endpoints and schemas.

## Build and test

```bash
cd scripts/syllable-cli
go build -o syllable .
go test ./...
```

CI ([test.yml](.github/workflows/test.yml)) runs `go test $(go list ./... | grep -v /integration)` on every push and PR. The `integration` package is excluded from CI by design — it requires live API credentials (see below).

## Test conventions

**Stubbed HTTP for unit tests.** The CI suite never hits a live API. See `setupTestServer` ([cmd/cmd_test.go:20](scripts/syllable-cli/cmd/cmd_test.go#L20)) for the canonical command-test pattern: it wires `apiClient` to an `httptest.Server` so you assert method, path, and body inside the handler. New commands should add a test mirroring `TestOutboundBatchesDelete` / `TestOutboundBatchesResults`.

A few special-case patterns to mirror, not reinvent:

- **Stdin (`--file -`)** — save/restore `os.Stdin` around an `os.Pipe`. See `TestDirectoryUploadStdin`.
- **Endpoint path contracts** — when slash placement matters (the API drops the `Syllable-API-Key` header on a 307 redirect), add an assertion to `internal/spec/spec_test.go`. See `TestBulkOperationPathsMatch`.

For everything else, `--dry-run` prints the request that would be sent without executing it — the safe smoke test when you don't want live calls.

### Live integration tests

`scripts/syllable-cli/integration/` is a black-box suite that builds the CLI binary as a subprocess and exercises it against a live Syllable instance. It is **opt-in**, run by the developer:

```bash
cd scripts/syllable-cli
SYLLABLE_API_KEY=... go test ./integration/...
# or
SYLLABLE_ORG=sandbox go test ./integration/...
```

The default org slug is `sandbox`. **Do not point integration tests at customer orgs.** Real customers (`nyp`, `hm`, etc.) appear in [AGENTS.md](AGENTS.md) examples — those are examples, not test targets.

## Branch and release workflow

- Feature branches; squash-merge into `main`. Commit titles end with `(#NN)`.
- Semver: `feat:` → minor bump, `fix:` → patch.
- Tag the merge commit and push the tag:

```bash
git tag -a vX.Y.Z -m "<short message>"
git push origin vX.Y.Z
```

(Tag annotation format is not standardized — recent tags use either the merged commit subject or just the version string. Match the most recent tag if unsure.)

- The `v*` tag triggers [.github/workflows/release.yml](.github/workflows/release.yml). GoReleaser then:
  - Runs `go test ./...` as a pre-release hook.
  - Builds darwin/linux/windows binaries for amd64/arm64 (windows/arm64 excluded).
  - Publishes the GitHub release with tarballs, zip, checksums, and `install.sh`.
  - Opens a PR titled `chore: update Homebrew cask for syllable vX.Y.Z` that updates `Casks/syllable.rb`. Merge after CI passes.

## Spec sync

The CLI develops against the embedded OpenAPI spec, sourced from the `main` branch of [asksyllable/syllable-sdk-typescript](https://github.com/asksyllable/syllable-sdk-typescript). When the backend ships a new spec, the `syllable-sync` skill ([.claude/skills/syllable-sync/SKILL.md](.claude/skills/syllable-sync/SKILL.md)) diffs the new spec against the embedded copy and reconciles the Go `cmd/` files.

## Convention notes

- All `--file` flags accept `-` to read from stdin. Multipart upload commands gained stdin support in v1.4.0; before that, `--file -` would silently fail by trying to open a literal file named `-`.
